<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Job handlers → scheduler | Handler code (later: network checks) may fail, hang or panic |
| System clock / power events → scheduler | Clock jumps and resume signals drive execution |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05-01 | Denial of Service | Job handler panic/hang | mitigate | Each run in its own `tokio::spawn` + `timeout`; panic → Failed; loop never exits on error (tests `panicking_job_is_failed_and_loop_survives`, `timed_out_job`) |
| T-01-05-02 | Denial of Service | Resume burst (N missed runs) | mitigate | Coalesced single run, `next_run_at = now + interval` (test `catch_up_no_burst`) |
| T-01-05-03 | Tampering | SQL in scheduler | mitigate | Static SQL with binds only (grep gate) |
| T-01-05-04 | Information Disclosure | Error text in job_runs | mitigate | Error messages truncated to 500 chars; handlers never receive secrets from the scheduler |
| T-01-05-05 | Denial of Service | Clock moved backwards | accept | Single-user local app; worst case is one delayed run; gap detector only fires on forward jumps |
</threat_model>
